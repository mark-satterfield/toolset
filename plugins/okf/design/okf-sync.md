# OKF Sync — design spec (draft)

Status: **implemented** 2026-07-10. Deterministic core in
`scripts/okf_tools/sync.py` (subcommands `plan` / `adopt` / `apply-deletions`);
orchestration in the `okf-sync` agent and `sync-okf-bundle` skill, surfaced as
`/okf:sync`. Decisions locked with Mark 2026-07-10.

Keep a bundle in sync with the source tree(s) it was built from: reflect changed
files, add new ones, drop deleted ones — without destroying curation, and
keeping the bundle shareable across machines.

## Non-goals

- Not a converter rewrite — reuses `references/conversion-guides.md` and
  `scripts/okf_tools/`.
- Not warehouse / live-data ingestion.
- Never touches hand-authored concepts (any concept without provenance is
  invisible to sync).

## Command surface

`/okf:sync <source> <bundle> [flags]`

- `<source>` is optional when the bundle's manifest already declares its source
  roots — then sync reconciles all of them.
- Flags:
  - `--tombstone` — on deletion, leave a deprecated stub instead of removing.
  - `--concept <id>` (repeatable) — reconcile only these.
  - `--dry-run` — print the plan (new / changed / deleted / unchanged), write
    nothing.
  - `--yes` — don't prompt; skip anything ambiguous rather than asking.

Small diffs run inline; large diffs delegate to an `okf-sync` agent.

## Provenance

Every sync-managed concept carries three extension keys (spec-safe — `type`
stays the only hard requirement):

```yaml
source_path: "$SKILLSPOKE_SHARED_DOCS/sdlc/mvp-1/prds/pricing-payment-and-runtime.md"
source_sha: "<sha256 of the source file's bytes>"
timestamp: "<ISO 8601 of the last sync that touched this concept>"
```

- `source_path` is stored in **env-var form**, never machine-absolute — this is
  what makes the bundle shareable.
- A concept with no `source_path` is hand-authored and sync ignores it.

## Source manifest — `sources.md` (bundle root)

`type: Source Manifest`. Declares each env var the bundle's `source_path`s use,
what tree it points to, and an example value. It is the portability contract:

```markdown
| Variable | Points to | Example |
|---|---|---|
| `SKILLSPOKE_SHARED_DOCS` | SkillSpoke shared-drive `docs/` tree | `$HOME/Library/CloudStorage/GoogleDrive-…/Shared drives/SkillSpoke/docs` |
```

Sync resolves paths from the **actual environment**, not from this file — the
manifest just tells a new machine what to set. A referenced var that isn't set
is a hard stop: "set `$SKILLSPOKE_SHARED_DOCS` — see `sources.md`."

## Change detection

1. Load bundle concepts that have `source_path`; expand `$VAR` → absolute; build
   a map `abs source path → (concept id, stored source_sha)`.
2. Walk the source root(s).
3. Classify each:
   - source file with no matching concept → **new**
   - matched, sha differs → **changed**
   - matched, sha equal → **unchanged** (skip)
   - concept whose `source_path` no longer resolves to a file → **deleted**

Binaries: hash the raw bytes; extract to markdown via the `to-markdown-util`
skill exactly as in conversion.

## Actions

- **new** → convert (per `conversion-guides.md`), place by **mirroring the
  source-relative path** under the bundle root (`$VAR/sdlc/…/x.md` →
  `<bundle>/sdlc/…/x.md`), stamp provenance. Ask only on a filename collision or
  when the source root isn't in the manifest.
- **changed** → re-derive the body from the re-converted source, write with the
  curation guards below, refresh `source_sha` + `timestamp`.
- **deleted** → **remove** the concept file (default). With `--tombstone`,
  rewrite it to a `type: Deprecated` stub that keeps the title/id and records the
  removal date, so inbound links still resolve to a gravestone.
- **unchanged** → skip.

Then reindex (`scripts/okf_tools/index.py <bundle>`) and validate
(`scripts/validate-okf.sh <bundle>`).

## Curation preservation (changed items)

Read-before-write (the reference agent's pattern), then:

- Preserve frontmatter keys the concept added beyond what conversion emits
  (hand-added tags, aliases, etc.).
- Augmentation guard: never shrink a `# Schema` or `# Citations` section.
- The **body is source-derived** — a re-sync re-derives it. Durable
  hand-curation belongs in frontmatter or a separate concept, not in a
  sync-managed body. (Same principle as the index-prose decision below.)

## Indexes & directory prose (decision #4 = A)

`index.md` is fully generated by `okf_tools/index.py` and is never hand-edited.
Directory narrative lives in an `overview.md` concept (`type: Doc`) that the
index lists like any other concept — and which shows up as a node in the viewer.
Neither convert nor sync ever folds prose into `index.md`.

## Deletion behavior (decision #3 = remove default, tombstone opt-in)

- Default: **remove** — the bundle tracks the source.
- `--tombstone`: leave a `type: Deprecated` stub (keeps title/id + removal date).
- Remove vs tombstone: *remove* deletes the file (links to it dangle, which OKF
  allows; git keeps history); *tombstone* keeps a marked stub so links resolve.

## Architecture

- `/okf:sync` command → `okf-sync` agent for large diffs; inline for small.
- Reuses `okf_tools`: `document` (parse/serialize/`validate_profile`), `paths`
  (id ↔ path), `index` (reindex).
- New `okf_tools/sync.py`: enumerate + hash a source tree, expand env-var paths,
  diff against provenance, drive the four actions. Deterministic core; the agent
  owns the per-file conversion judgment.

## Open / deferred (v1)

- Renames/moves surface as delete + new — no rename detection in v1.
- A sync-managed body that was hand-edited: the guard protects
  schema/citations, but arbitrary prose edits are overwritten on re-sync.
  Documented, not solved in v1.
